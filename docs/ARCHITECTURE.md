# 马斯克技能包 · 从零重设计的架构

## 一、先立判据（之前两次切分都错在判据上）

Anthropic 官方规范里那条最要紧的话：

> If certain contexts are **mutually exclusive or rarely used together**,
> keeping the paths separate will reduce the token usage.

**切分的唯一判据 = 「会不会总是一起用」。**

| 判据 | 结果 |
|---|---|
| 总是一起用 | **必须同文件**，拆开就是白拆（模型两边都得读） |
| 互斥 / 很少一起用 | **必须分开**，这样省 token |

**我过去犯的两个错：**

1. 按**主题**切（playbooks 按领域）→ 招人、组织、工程各一节，但它们和「原则」「案例」总是要一起看
2. 按**形态**切（methods = 动作 vs playbooks = 判断）→ 这个判据根本不成立，因为大量条目既含判断也含动作，结果两边重复讲「愿望思维」「速度」「复杂度」

## 二、三层结构（官方 progressive disclosure）

| 层 | 内容 | 何时进上下文 | 我们对应什么 |
|---|---|---|---|
| **L1** | `name` + `description` | **启动时全部预载** | frontmatter |
| **L2** | `SKILL.md` 正文 | 技能被触发时读 | **目标 <500 行** |
| **L3** | 捆绑文件 | 按需读 | references/*.md + corpus/ |

**当前违规**：L2 = **769 行**，超 54%。规范说 `<500`。

## 三、按「一起用」重新分组

### 每一轮回答都需要的（→ L2，进 SKILL.md）
- 我是谁（身份卡）
- 我怎么说话（腔调 / 情绪 / 幽默 / 边界）
- 我怎么看世界（**11 条原则的紧凑形态**）
- 我怎么下判断（十道闸）
- 我需要时该去翻哪个文件（路由表）

### 只在特定处境下需要的（→ L3）
- 撞上某个具体处境 → **情境手册**
- 要证明他说过 → **引文库**
- 腔调跑偏 → **语感样本**
- 要深挖原文 → **语料**

**关键判断**：11 条原则的**全量版**（逐字原文 + 失效边界 + 落地动作，477 行）**不是每轮都需要的**。绝大多数回答，紧凑形态够了；只有当这条原则是答案核心时，才需要全量。

## 四、目标结构（7 个文件 → 5 个）

```
elon-musk-wisdom/
│
├── SKILL.md                    L2 · 目标 380–450 行
│   ├── frontmatter              name + description
│   ├── 身份卡
│   ├── 人格
│   │   ├── 腔调（句式/词汇/确定性分界）
│   │   ├── 情绪与幽默          ← 现在完全没有，要补
│   │   ├── 跟用户的关系（称呼/亲近度/怎么不同意）
│   │   ├── 自我认知（我哪里不行）  ← 已有，并入
│   │   └── 边界规则
│   ├── 路由表                   ← 唯一的入口，全包只有这一张
│   ├── 11 条原则（紧凑）         主张 1 行 + 核心判据 2–3 行 + 指针
│   └── 十道闸（紧凑）
│
├── references/
│   ├── principles.md           11 原则全量版（逐字原文 / 机制 / 失效边界 / 落地动作）
│   ├── situations.md           情境手册 = playbooks + methods + cases 三合一
│   ├── evidence.md             逐字引文库（引用时的唯一权威）
│   ├── voice.md                语感样本（补幽默/情绪/讽刺）
│   └── corpus-index.md         258 份语料的地图
│
└── corpus/                     258 份原始语料
```

**关键点：`principles.md` 与 SKILL.md 里的原则紧凑版不重复内容。**
- SKILL.md 只有：主张 + 判据 + 指针
- principles.md 只有：逐字原文 + 机制详述 + 失效边界 + 落地动作

**零重复 = 零同步风险**（这才是我上次拆分失败的真正原因：两处写同一件事，必然分叉）

## 五、情境手册的统一条目格式

`playbooks`（40 节）+ `methods`（39 条）+ `cases`（27 个）合并。判据：**同一个用户问题会不会同时命中两条？会，就合并。**

```markdown
## <编号>、<用他的说法起标题>

**什么时候用**  什么处境该翻这一条（判据要具体到能对上号）

**我怎么看**    2–4 句判断 + 一条逐字原文

**怎么做**      编号步骤（有则写；没有就省略——这条讲的是怎么看）

**什么时候不成立**  失效边界（必须写）

**先例**        情境 / 决策 / 结局（有则写）
```

**术语统一**（官方硬要求）：全包只用这一套词
- 「原则 N」——不叫 cluster_00X
- 「条目 N」——不叫「第 N 节」也不叫「M01」
- 「证据卡」——不叫「引文」「名言」
- 「语感样本」——不叫「voice 样本」
